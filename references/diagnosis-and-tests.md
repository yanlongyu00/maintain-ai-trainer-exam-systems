## 反馈分级

| 级别 | 判断 | 处理重点 |
| --- | --- | --- |
| P0 | 数据泄露、全部用户不可用、错误发布 | 立即保护线上可用版本，先止损再修复 |
| P1 | 核心考试/判分阻断、进度污染、广泛打不开 | 快速复现、最小修复、完整回归 |
| P2 | 单题错误、移动端布局、文案歧义、部分网络 | 核验证据后修复，避免过度设计 |
| P3 | 体验建议或新功能 | 与缺陷分开排期，不伪装成紧急修复 |

## 通用诊断

1. 复述用户操作路径，区分预期和实际结果。
2. 先验证顾客输入是否与页面已有代码片段重复，避免把文案歧义误判为算法错误。
3. 检查正式链接和备用链接是否为同一功能版本。
4. 检查浏览器控制台、失败请求、缓存头和第三方 CDN。
5. 检查是否只在特定设备、学校 Wi-Fi、无 VPN 或首次冷启动出现。
6. 用最小复现隔离：内容数据、业务逻辑、持久化、布局、依赖、托管。
7. 对题目答案分别标注母库、模拟卷、教材/原始资料和推理结论，不能把内部标签当成官方证明。

## 理论系统

### 必测状态

- 两道题题型和题号相同、内容不同，能分别保存与重测。
- 模拟题和练习题相同编号不会互相替换。
- 提前交卷时未作答题不进入错题本。
- 重复答错同题时更新正确，不生成冲突记录。
- 刷新后答案、进度和错题仍对应原题。
- 旧 schema 数据迁移后保留有效错题，清理明确无效记录。
- 主域名和备用域名分别说明本地存储，不声称跨域同步。
- 普通刷题和模拟考试不出现重点标记；错题本内可以设为/取消重点，刷新后状态和筛选数量正确。
- “重测全部”包含全部错题，“只练重点”只包含重点错题；重测过程不覆盖普通刷题进度。
- 在错题本答对一次仍保留；手动确认“已掌握”后移出；以后再次答错时作为普通错题重新加入。
- 旧版 `mastered:true` 迁移后题目仍保留，不能批量误删。
- 错题本判断题、单选题点击选项立即判分并锁定；多选题选择时不自动判分，仍由“查看答案”触发。
- 重点筛选后操作使用原错题索引，不因隐藏普通错题而标记、判分或删除错题。

### 题库争议

优先级不是固定“AI 常识 > 母库”，而是：先找用户认可的原始答案来源，再核对题干、选项顺序和答案串位置。存在冲突时输出证据层级，不擅自修改已售卖题库。

## 实操系统

### 必测界面

- 40 道题目录完整，抽查首题、中间题、最后一题。
- 默认收起和展开都不吞掉后续模块。
- 原题图片 `max-width: 100%`，窄屏无横向滚动。
- 手机宽度下标题、代码框、答案提示和按钮可读可点。
- 原题提取不包含作答提示、注意事项和答案上传区。
- 访问控制、学习进度和一键重置仍正常。
- 正式版不存在预览版绕过访问控制或固定跳题代码。

### 内容生成

若从 40 个原题 HTML 生成内嵌数据，生成器必须：

- 报告匹配数量和缺失题号；
- 对 HTML 片段做标签/结构检查；
- 生成后抽查至少三题；
- 把数据直接放入发布产物或明确携带依赖文件，避免部署漏资源。

## 考场系统

### 三层结果契约

涉及模型得分、MSE、R²、准确率等输出时分别检查：

1. **右侧标准输出**：从用户认可的练习报告或结果文件提取，固定展示并保留来源；不要通过网页临时运行反推。
2. **本次运行结果**：由浏览器当前数据、随机划分和依赖版本产生，可以与右侧数值不同。
3. **判分依据**：正确代码与同一网页环境的基准执行结果，或兼容模式下的关键填空匹配；固定展示值不参与真实运行值比对。

界面验收要求：

- 右侧所有卡片统一写“标准输出”；不出现内部来源术语。
- 只在有固定标准值且成功产生运行结果的步骤下方显示差异说明。
- 差异说明位于运行数值之后，明确“练习环境可能不同，考试中以右侧标准答案为参考”。
- 无输出步骤不添加环境差异说明；错误答案仍显示对应错误，不用说明文案掩盖失败。
- 正常 Python、兼容回退和刷新后恢复三条路径使用同一文案与位置。

### 五层契约

代码题正确运行需要同时满足：

1. 代码模板拼接语法正确；
2. 依赖存在且版本兼容；
3. 测试数据字段、类型和缺失值符合题目假设；
4. 前后步骤命名空间和回放状态正确；
5. 判分程序不吞掉标准答案自身的错误。

### 必测路径

- 从冷启动运行一题的全部步骤。
- 正确答案通过；每个填空故意错误时只报告对应错误。
- 正常 Python 模式与兼容回退模式结果符合既定口径。
- 固定标准输出与本次运行结果同时存在时，来源、标签和判分互不污染；故意制造数值不同仍能正确判分并显示说明。
- 进入技能考核后预加载，首次运行不会无限“运行中”。
- 超时后本会话不反复等待；迟到加载不逆转已锁定模式。
- 运行期间返回、切题或切卷，不把结果写入另一题。
- 刷新页面后进度与运行命名空间恢复一致。
- 本地 wheel 和其他随包依赖返回成功并能导入。
- 断开外部 CDN 时仍能按设计回退，不夸大为真实 Python 执行。

## 对抗式审查矩阵

| 攻击条件 | 预期 |
| --- | --- |
| 重复题号、不同题干 | 记录不覆盖、不串题 |
| 未作答后交卷 | 不进入错题本 |
| 旧版 localStorage | 自动迁移或明确提示，不粗暴清空 |
| 运行中快速切题 | 结果绑定原 task，不拉回或污染当前页 |
| CDN 超时/断网 | 在总超时内回退，页面可继续操作 |
| 首次冷启动 | 有状态提示和上限，不无限等待 |
| 320px 窄屏 | 无横向溢出、关键按钮可用 |
| 图片/超长代码 | 自适应且不破坏折叠结构 |
| 浏览器缓存旧版 | 能辨别版本并给出刷新方案 |
| 主站新版、备用站旧版 | 发布前发现漂移，发布后分别验收 |
| 预览绕过访问控制 | 不得进入生产产物 |
| 发布包多套一层目录 | 阻止发布并重新打包 |
| 固定标准值与运行值不同 | 右侧仍为标准输出；运行区解释差异；正确代码通过、错误代码失败 |

## 本机预览验收

- 预览文件与已测试候选哈希一致，HTTP 返回 200。
- 预览链接可点击，并明确仅限当前电脑、尚未发布。
- 预览中完成原反馈路径、正确路径和故意错误路径；不能只看首页。
- 用户根据预览追加修改后，更新同一预览链接并重跑相关测试。
- 发布产物不得包含临时绕过访问控制、固定测试数据或仅为预览添加的代码。

测试报告按“通过 / 失败 / 未验证”逐项写证据。没有执行不能写“通过”。
