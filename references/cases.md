## 理论错题串题与答案争议

来源：真实维护任务（编号已脱敏）

- 表象：顾客认为错题本出现别人的题，或答案与题库不同。
- 根因一：用“题型 + 题号”关联题目，模拟题与练习题编号重复。
- 根因二：未作答被当成答错。
- 正确处理：保存稳定题目标识和原题快照；重测直接读取快照；旧数据迁移；未作答不入错题。
- 证据纪律：系统标签“官方模拟卷答案”不自动等于官方机构答案，需回查原模拟卷题号和答案串。
- 产品判断：单人使用产品不因极少数共享浏览器场景增加多档案复杂度。

## 实操原题内容与双平台发布

来源：真实维护任务（编号已脱敏）

- 表象：精简任务字段不足；折叠后出现大空白；手机图片可能溢出。
- 根因：原素材 HTML 的多余关闭标签破坏折叠 DOM；图片缺少响应式限制。
- 正确处理：先做单题预览，再批量提取 40 题；排除作答提示和答案上传；保留访问控制与进度；内嵌数据避免漏资源。
- 审查发现：预览版可能绕过访问控制或固定在某题，不能直接覆盖生产版。
- 发布要求：Netlify 与妙搭分别上线和在线抽查。

## 考场 Python 卡死与兼容回退

来源：真实维护任务（编号已脱敏）

- 表象：点击“运行全部代码”长时间停在运行中。
- 根因：页面加载成功不等于外部 Python CDN 可达；旧版只限制脚本加载，未覆盖 Pyodide 初始化和依赖下载的总等待。
- 正确处理：提前预加载、总超时、会话锁定兼容模式、标准输出回退。
- 对抗式审查又发现：部分加载后的等待可能绕过超时；运行中切题会误写另一题；迟到 Promise 会改变模式。
- 依赖审计还发现：第三方库缺失、版本不兼容、测试数据违背题目假设、旧 pandas API、代码模板缩进和标准答案错误被吞掉。
- 正确测试：真实执行全部 Python 题；正确/错误/重置/刷新/冷启动/切题/断网同时覆盖。
- 产品约束：用户明确要求保留已确定的简单文本比对逻辑，不因审查顺手改判分策略。

## 理论错题保留、重点标记与预览迭代

时间：2026-07-24

- 初始反馈：顾客希望错题答对后不要自动消失，并能反复练习容易错的题。
- 产品边界：重点标记只出现在错题本；答对一次仍保留；用户确认“已掌握”才移出；以后再次答错按普通错题重新加入。
- 迁移要点：旧版 `mastered:true` 是系统自动行为，不能解释成用户主动掌握并删除；迁移后保留为普通错题。
- 预览价值：本机预览暴露了“选择答案后还要点击查看答案”的多余步骤。最终只让判断题、单选题点击即判分，多选题保持原流程，避免无法判断用户何时选完。
- 相邻保护：错题重测不能覆盖普通刷题进度；重点筛选下的按钮必须使用原错题索引。
- 发布经验：Netlify 单页更新包保留当前线上实操页和考场页；用户有多个账号时交付拖拽包并等待上传完成。妙搭复用原 app_id，保留其不蒜子移除差异，发布后用线上文件哈希和回归测试验收。

## 考场标准输出、运行结果与双平台交接

时间：2026-07-25

- 初始反馈：代码填写正确但 Python 环境偶发失败；随后发现部分模型题右侧没有指标输出。
- 产品澄清：右侧是供备考记忆的“标准输出”，应使用用户认可的已完成练习报告数值；网页内置数据产生的是本次运行结果，两者可能不同。
- 三层分离：固定标准输出只负责展示；正常 Python 判分使用正确代码与同环境基准；网络兼容模式按关键填空判分并显示网页练习环境参考结果。
- 文案迭代：不要在右侧区分“原练习资料参考输出”等内部名称；全部统一“标准输出”。只在成功运行结果下方解释环境差异，并明确考试中以右侧标准答案为参考。
- 来源纪律：报告文件中的完整精度按页面既定显示格式取舍；不能把浏览器临时生成数值写回标准答案。
- 发布交接：用户负责把确定性 ZIP 拖到目标 Netlify 项目；助手按用户要求发布既有妙搭应用。必须逐平台说明操作者和完成状态，不能交付 Netlify 包后遗漏妙搭。
- 故障处理：妙搭 dry-run 通过、正式上传首次遇到 EOF 时按同参数重试一次；成功后检查公开且免登录，再下载线上 HTML 核对版本与哈希。
- 线上证据：Netlify 页面、根入口、两个 wheel 依赖和正常 Python 完整运行都要验收；妙搭销售链接至少核对标题、版本、关键文案和公开范围。
